# Итоговый проект "TODO manager"

## Описание
Это итоговый проект по курсу Go для начинающих. Требуется выполнить задание на создание веб приложения управления задачами.

## Что было выполнено из заданий с повышеной сложностью:
* Разбор переменных окружения для имения BD файла и номера порта сервера
* Авторизация по JWT
* Запуск в docker контейнере, с мапингом на локальную папку 

## Локальный запуск

Для запуска локально, достаточно выполнить команду корневой директории проекта: 
```
go run cmd/main.go
```
Порт сервера, по умолчанию: `7540`

### Номер порта сервера
При желаении указать другой номер порта, перед запуском можно определить переменную окружения `TODO_PORT`: 
```
export TODO_PORT=8080
```
Так же можно указать порт вместе с командой запуска приложения: 
```
TODO_PORT=<NUMBER> go run cmd/main.go
```
Сервер в лог консоли напишет, какой порт используется в текущий момент.

### Имя файла для базы данных
Имя файла BD по умолчанию: `scheduler.db`

Переопределить имя для файла BD можно, через переменную окружения `TODO_DBFILE`: 
```
export TODO_DBFILE=newfilename.db
```
или по аналогии с портом, вместе с командой запуска сервера:
```
TODO_DBFILE=newfilename.db go run cmd/main.go
```

### Задание пароля для сервера
Пароль для сервера задается через переменную окружения `TODO_PASSWORD`: 
```
export TODO_PASSWORD=<SOME_PASSWORD> 
```
или вместе с запуском с командой запуска сервера:
```
TODO_PASSWORD=<SOME_PASSWORD> go run cmd/main.go
```

## Запуск приложения в конейнере
### Подготовка к сборке образа
В репозитории уже имеется `Dockerfile`. Перед сборкой образа, необходимо собрать приложение в инсполняемый файл из корня проекта.\
Имя конечного файла, должно быть `todo_srv`. Пример сборки для linux (x86_64):
```
$ CGO_ENABLED=0 GOOS=linux GOARCH=amd64 go build -o todo_srv ./cmd/main.go
```

### Сборка образа
Собрать образ можно данной командой:
```
$ docker build -t todo-img:v1 -f ./Dockerfile .
```

### Запуск контейнера
#### Запуск без параметров окружения
Простой запуск, например:
```
docker run -v <PATH_TO_DIR>/:/web/db/ -p 7540:7540 --name todo-final todo-img:v1 
```
В этом случае, сервер будет работать без авторизации, порт будет стандартный `7540`.\
Что бы приложение создало DB или могло использовать локальный файл DB (находящийся на хосте), неодходимо добавить мапинг дикректории в контейнер.\
В данном примере, `PATH_TO_DIR` подразумевает путь к директории на хосте, которая будет проброшена в директорию `/web/db` в контейнере.

В противном случае, без указания мапинга директории, файл BD будет создан внутри контейнера.

#### Запуск с параметрами окружения
В `Dockerfile` определены следующие параметры окружения:
```
ENV TODO_PORT=""
ENV TODO_DBFILE="db/scheduler.db"
ENV TODO_PASSWORD=""
```

Пример старта контейнра с параметром окружения, `TODO_PASSWORD` и `TODO_DBFILE`:
```
$ docker run --rm -e TODO_DBFILE=db/test.db -e TODO_PASSWORD=qwe123 -v $PWD/db/:/web/db/ -p 7540:7540 --name todo-final todo-img:v1 
```
При указании переменной `TODO_DBFILE`, необходимо добавлять к имени файла имя директории `db/` (враппер писать не стал), как указано в примере.

Использовать переменную окружения `TODO_PORT` особого смысла нет, так как `docker` позволяет мапить порт приложения, на нужный порт хоста.\
Если требуется ихменить номер порта у приложения, при добавлении переменной окружения `TODO_PORT`, необходимо поменять порт в мапинге:
```
$ docker run --rm -e TODO_DBFILE=db/test.db -e TODO_PASSWORD=qwe123 -e TODO_PORT=8080 -v $PWD/db/:/web/db/ -p 7540:8080 --name todo-final todo-img:v1 
```
в примере выще, мапинг `-p 7540:8080` отражает изменение номмера порта в переменной окружения `TODO_PORT`.

## Тесты и фронтенд
В директории `tests` находятся тесты для проверки API.

Директория `web` содержит файлы фронтенда.

### Запуск тестов
Для запуска всех базовых тестов достаточно выполнить команду из корня проекта: `go test ./tests`

Переменная в `var Token` в `tests/settings.go` уже выставлена в соотвествии с тестовым паролем `qwe123`.\ 
При изменении пароля и желании провести тесты - необходимо изменить токен, на созданный сервером. Сервер выведет токен в консоль после создания.
